71// Custom Notched Shape for BottomAppBar
72class CustomNotchedRectangle extends NotchedShape {
73  const CustomNotchedRectangle();
74
75  @override
76  Path getOuterPath(Rect host, Rect? guest) {
77    if (guest == null) return Path()..addRect(host);
78
79    final notchRadius = guest.width / 2 + 8;
80    final s = guest.center.dx - notchRadius;
81    final e = guest.center.dx + notchRadius;
82
83    return Path()
84      ..moveTo(host.left, host.top)
85      ..lineTo(s, host.top)
86      ..quadraticBezierTo(guest.center.dx, guest.top + 20, e, host.top)
87      ..lineTo(host.right, host.top)
88      ..lineTo(host.right, host.bottom)
89      ..lineTo(host.left, host.bottom)
90      ..close();
91  }

❓ Tại sao chọn Riverpod thay vì BLoC?

Giải thích quyết định kiến trúc State Management

🎯 5 Lý Do Chính:

  • 1. Ít Boilerplate Code (~70% ít hơn BLoC):
    • Riverpod: 1 file (Provider + Notifier)
    • BLoC: 3-4 files (Event, State, Bloc, Repository)
  • 2. Không cần BuildContext:
    • Riverpod truy cập state ở bất kỳ đâu (Services, Repositories)
    • BLoC bắt buộc có BuildContext → khó dùng trong ChatService, NotificationService
  • 3. Tự động Dispose:
    • Riverpod tự quản lý lifecycle
    • BLoC cần close() thủ công, dễ memory leak
  • 4. Compile-time Safety:
    • Phát hiện lỗi ngay khi build, không phải runtime
  • 5. Phù hợp quy mô Project:
    • App e-commerce vừa (~23 screens, team 4 người)
    • BLoC phù hợp hơn cho enterprise apps lớn
